# Contributing

Thank you for helping improve CoolHack Cyber Academy.

## Before contributing

1. Open an issue describing the problem or teaching need.
2. Do not include credentials, active team codes, personal data, grades, real
   incidents, or private answer keys.
3. Keep student-facing explanations educational without revealing mission
   conclusions.
4. Use fictional names, domains, IP addresses, and evidence.

## Development

1. Fork the repository.
2. Create a focused branch.
3. Make the smallest coherent change.
4. Test desktop and mobile behavior.
5. For database changes, test with separate administrator, pending professor,
   assigned professor, and two-team student accounts.
6. Update documentation and `CHANGELOG.md`.
7. Search the diff for secrets and personal data.
8. Open a pull request describing the change, reason, impact, and tests.

## Content standards

- Define meaningful cybersecurity acronyms.
- Explain why a concept matters without giving away the case answer.
- Use accessible labels, keyboard-operable controls, and readable contrast.
- Preserve the four-role, shared-report, shared-AI-transcript, and individual
  reflection model unless a proposal explicitly changes the pedagogy.
- Keep vendor references optional and avoid implying institutional endorsement.

## Security changes

Any authentication, SQL, row-level security, membership, reflection, or staff
role change requires the complete security checklist. A visual test alone is
not sufficient.

Report vulnerabilities privately when possible. Do not publish exploit details
or active deployment information before maintainers can respond.
